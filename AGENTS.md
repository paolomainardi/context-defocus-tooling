# AGENTS.md

## Project Overview

Static HTML dashboard cataloguing token optimization and context management tools for AI coding agents (Claude Code, GitHub Copilot, OpenCode). Zero build system, zero dependencies. Data-driven via `tools.json` (human-curated) + `metrics.json` (auto-generated by GitHub Action).

**Tech stack:** Vanilla HTML/CSS/JS. No frameworks, no bundler, no npm. Google Fonts loaded externally. Data loaded via `fetch()` at runtime.

**Live site:** Served via GitHub Pages from `main` branch root.

## Setup

No install step. The site is a single `index.html` loading two JSON files.

```bash
python -m http.server 8000
# Open http://localhost:8000
```

`file://` protocol will not work (fetch requires HTTP). Any static server works.

## Key Conventions

- **Self-contained HTML**: all CSS lives in a `<style>` block, all JS in a `<script>` block. No external JS dependencies.
- **Data separation**: tool catalogue data lives in `tools.json`. Machine-fetched metrics live in `metrics.json`. The HTML loads both at runtime and merges by `id`.
- **No build system**: there is no bundler, no transpiler, no minifier. Edit the files directly.
- **No analytics or tracking**: the site must never include tracking scripts, pixels, or third-party analytics.
- **Fonts are the only external resource**: Google Fonts (JetBrains Mono, Fraunces, IBM Plex Mono).

## How to Add a Tool

Edit `tools.json`. Each tool entry has this schema:

```json
{
  "id": "unique-kebab-id",
  "name": "Display Name",
  "vendor": "owner/repo",
  "url": "https://github.com/owner/repo",
  "failure": "1",
  "failureLabel": "FAIL MODE 01",
  "tagline": "One-paragraph description of what it does and how.",
  "meta": {
    "License": "MIT",
    "Distribution": "npm · pip",
    "...": "other key-value pairs shown on the card"
  },
  "maintainer": "solo|team|vendor",
  "language": "Rust|Python|TypeScript|Go|Shell|Markdown",
  "license": "MIT|Apache-2.0|BSD|Custom",
  "indepEval": false,
  "compactDesc": "Short one-line description for compact view",
  "observations": [
    "Factual observation with source attribution.",
    "Another observation."
  ],
  "stars": 100,
  "lastRelease": "2026-05"
}
```

**Required fields:** `id`, `name`, `vendor`, `url`, `failure`, `failureLabel`, `tagline`, `meta`, `maintainer`, `language`, `license`, `indepEval`, `compactDesc`, `observations`, `stars`, `lastRelease`.

**Notes:**
- `stars` and `lastRelease` are seed values — they get overridden by `metrics.json` once the GitHub Action runs.
- `maintainer` is a qualitative editorial judgment: `"solo"` (single author), `"team"` (multiple substantive contributors), `"vendor"` (commercial entity).
- `indepEval` means a third-party (not the tool's author/vendor) has measured the tool's claims.
- `failure` values: `"1"` through `"5"`, `"x"` for cross-cutting. Use `"1+3"` for tools spanning multiple modes.
- `observations` must be factual, sourced, and written in third person. No recommendations.

## Risk Dot Computation

Risk is computed mechanically from four signals in `index.html`:

| Level | Criteria |
|-------|----------|
| **low** | (≥10k stars OR team/vendor) AND has independent eval AND recent release |
| **mid** | 1k–10k stars; OR solo+eval; OR vendor without recent release |
| **high** | <1k stars AND solo AND no eval |
| **crit** | <50 stars AND solo AND no eval AND no release in 6+ months |

"Recent release" = `lastRelease >= '2025-11'` (within ~6 months).

## Metrics Auto-Refresh

The GitHub Action (`.github/workflows/refresh-metrics.yml`) runs daily at 06:00 UTC and:
1. Reads `tools.json` for GitHub URLs
2. Fetches stars, latest release date, contributor count from the GitHub API
3. Writes `metrics.json`
4. Commits and pushes if changed

The default `GITHUB_TOKEN` is sufficient (public repos, ~21 API calls/run).

## Git Workflow

### Commits

Follow [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/):

```
<type>(<scope>): <description>
```

**Types:** `feat`, `fix`, `refactor`, `docs`, `chore`, `ci`.
**Scope** is optional — use `data` for tools.json changes, `ui` for index.html, `ci` for workflow.

Keep the description lowercase, imperative, no period.

### Branching

- Branch naming: `feat/`, `fix/`, `chore/`, `docs/` prefix + kebab-case description
- Never push directly to `main`. Always create a feature branch and open a pull request.

## Code Style

- **HTML**: single file, no partials. CSS in `<style>`, JS in `<script>`.
- **CSS**: custom properties in `:root`, BEM-like class names (`.tool-card`, `.tool-name`, `.risk-dot`).
- **JS**: vanilla ES2020+. No modules, no imports. Global state in the `state` object. Functions for rendering, filtering, sorting.
- **JSON**: 2-space indent, trailing newline.

## Command Safety

### Safe (run autonomously)

- `python -m http.server` — local dev server
- `git status`, `git log`, `git diff`
- `node -e "..."` — data extraction/validation scripts

### Dangerous (ask user first)

- `git push`
- `gh repo create`
- `gh api` calls that modify state

### Destructive (never run)

- `rm -rf`
- `git push --force`
- Deleting `tools.json` or `index.html`

## Important Rules

- Never add a build system, bundler, or transpiler.
- Never add external JavaScript dependencies or CDN imports.
- Never add analytics, tracking, or telemetry to the site.
- Keep `index.html` self-contained (aside from JSON data fetches and Google Fonts).
- Contributors only edit `tools.json` — never commit manual edits to `metrics.json`.
- All tool observations must be factual and source-attributed. No recommendations, no opinions.
- The risk dot is mechanical — argue with the thresholds, not the output.
